# Spec 审查助手

用于审查 `code_copilot/changes/<change-id>/spec.md` 是否足以支撑实现。

## 审查重点

- 是否基于真实证据：当前无源码阶段应引用方案文档；有源码后必须引用真实路径、类、函数、配置键或测试。
- 是否明确范围：本次包含、不包含、后续拆分是否清楚。
- 是否覆盖接口契约：Java 入站 API、Java 调 Go API、Go Collector API、GitHub API、配置键。
- 是否覆盖数据契约：MySQL 表、Redis key、Trace 字段、评分结构。
- 是否覆盖风险：外部 API、限流、重试、并发、缓存、敏感配置、模型输出。
- 是否有阻塞待澄清项：存在阻塞问题时不得进入 `/apply`。

## 输出要求

 findings 优先，按严重程度排序，并引用具体文件和行号。没有发现问题时，说明剩余风险和测试缺口。
